## 改了什么 (`scripts/qqq_leap.py` apply)

买入分支从「无条件 `positions[occ] = {...}`」改为「无则新建 / 有则合并」:

| 字段 | 合并规则 |
|---|---|
| `contracts` | 相加 |
| `entry_cost_usd` | 相加 (各笔实际成交额) |
| `entry_fill_price` | **加权均价** `(p0×n0 + p1×n1)/(n0+n1)` |
| `take_profit_line` | 加权均价 × `take_profit_mult` |
| `_lots` | 追加一笔 {date, contracts, fill_price}; 老仓位无该字段时从现有字段合成首笔 |
| `entry_date` | **不动** |
| `entry_delta` / `entry_dte` / `entry_spread_pct` / `entry_spot` / `entry_day_return_pct` | **不动** (开仓快照) |

`entry_date` 不动的依据是 config 里本来就有的 `exit.holding_clock_resets=false` ——
该字段正是为这件事存在的, 与 RSI-2 轨道「时间止损时钟不因加仓重置」同一纪律。
设成 true 才按本次成交日重置 (代码已按配置分支)。

### 顺带补的守卫 (非用户要求, 但合并使它成为必需)

合并后仓位可以 >1 张, 于是「卖的张数 ≠ 持有张数」**第一次变成现实风险**;
而原代码是无条件 `positions.pop(occ)`, 会让账本静默丢掉剩下的张数。
现在不相等即 `SystemExit` 并说明原因。引擎出场一律整仓卖
(`signal` 的 sells 用 `contracts=持仓张数`), 故不相等就是对账出了问题。
