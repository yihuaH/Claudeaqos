## 7. 追查: 15:20 主跑为什么被拒 (用户问)

### 7.1 拒绝来自平台层, 不是券商/仓库/Routine 配置

错误原文:
> `Permission for this action was denied by the Claude Code auto mode classifier.`
> `Reason: [Real-World Transactions]`

即 **Claude Code 自身的 auto-mode 权限分类器**。与 Robinhood、与 `trig_01Pqeuv...` 的配置本身、
与仓库状态**都无关** —— 那个 Routine 的 cron/prompt/连接器至今完好, 只是 `enabled` 停在 false。

### 7.2 为什么只拦它一个 —— 三个调用的差别只在「被启用的 Routine 存了什么 prompt」

三次调用**形状完全相同** (`update_trigger` + `enabled=true`), 两个过、一个拒。唯一变量是各自
Routine 的 prompt 文本。逐词数:

| 关键词 | 晨检 10:45 ✅ | wrapup 17:45 ✅ | **收盘前主跑 15:20 🔴** |
|---|---|---|---|
| `place` | 0 | 0 | **4** |
| `买单` | 0 | 0 | **4** |
| `下单` | 0 | 0 | **2** |
| `review` | 0 | 0 | **2** |
| `buy_to_open` / `auto_buys` | 0 / 0 | 0 / 0 | **1 / 1** |
| **下单类词合计** | **0** | **0** | **14** |

且晨检与 wrapup 的 prompt 里都**明文写着「不交易」**(「不做任何交易/撤单动作」/「按红线6 不交易」),
而 15:20 的 prompt 通篇是 `直接 review → place`、`execution.mode=auto_buys`、`绝不动用借来的钱`。

=> 分类器几乎确定是**读 prompt 文本**判定「启用它 = 授权一条会动真钱的自动交易流程」。

### 7.3 ⚠️ 由此得到一个反讽但要紧的结论: **这道闸量的是措辞, 不是实际能力**

**真正能下单的不止 15:20。** 17:45 wrapup 在当日无 `preclose: completed` 标记时会
**fail-safe 退化为完整主跑, 照样下买单卖单** (`daily.py` 的 wrapup_fallback 分支) ——
但它的 prompt 里**一个下单词都没有**, 于是**放行了**。

📌 **所以: 分类器放行 ≠ 这条任务不会动钱; 分类器拦下 ≠ 那条任务更危险。**
它是一道**文本层**的闸, 不是能力层的闸。这不是说它没用 (它确实拦住了最露骨的那条),
而是**不能把它当作「钱不会动」的保证**。本条应记入平台层认识, 与 CLAUDE.md 既有的
分类器条目同族。
