# 2026-10-23 QQQ LEAP 改为三档梯子 (用户「以后qqq跌了 买三个期权」)

## 为什么先问再做

用户原话「以后qqq跌了 买三个期权」有三种读法, 钱差很多, 故按"不同读法导致实质不同的工作"
问了一次:

| 读法 | 规模 (当日价) | 改法 |
|---|---|---|
| 3 张同一合约 | 330档 $7,320 = 净值 74.6% | 只改 `position_pct_of_portfolio` |
| **3 个期限各 1 张** ← 用户选 | 约 $5,240 = 53.4% | **要改引擎** (每信号从选 1 张变成选 3 档各 1 张) |
| 并持上限 3 张 | 不变 | 基本空操作 (`max_concurrent_positions=null` 且 §17.3 回测显示牛市过滤已把并持自然封顶在 3) |

同时先讲清两件会让指令失效的事:

1. 🔴 **「整单跳过不缩量」会吃掉它**。红线9 的防杠杆闸按单笔判, 一张 330 DTE 约 $2,440,
   三张 $7,320 = 净值 74.6%, 账户几乎永远凑不出 → 要 3 张而现金只够 1 张时结果是 **0 张**。
   照"3 张同一合约"的字面实现, 10-22 那笔成功的买入以后会变成不买。
2. 引擎给 1 张是算出来的不是写死的: `target = pv×20% = $1,961`, `qty = floor(1961/per)`,
   330 档 $2,440 → 0 张 → 走贵档例外给 1 张。

## 实现

### 配置 `contract.ladder`

```json
[ {"target_dte_calendar": 148, "dte_band_calendar": [120, 190]},
  {"target_dte_calendar": 85,  "dte_band_calendar": [60, 110]},
  {"target_dte_calendar": 330, "dte_band_calendar": [300, 400]} ]
```

- **带宽互不重叠** (191~299 的空档是故意的)。重叠会让两档选到同一 OCC, 而 apply 的同键合并
  (10-22 刚加的) 会把「3 个期限各 1 张」**静默退化成「某期限 2 张」**。
- **列表顺序 = 资金优先级, 由 config 声明, 引擎不自排** (红线2)。
  现行 148 → 85 → 330 的依据:
  · `qqq-leap-dte-verdict.py` (10-22): **148 是唯一在收盘/盘中两种实测摩擦下都显著优于 330**
    的档 (+10.60% p=0.000 / +5.83% p=0.008); 85 仅宽摩擦显著 (p=0.001, 紧摩擦 p=0.060);
    330 最差 (被 9.94% 实测点差吃掉)。
  · `qqq-leap-tp-85-148.py` (10-23): 85 档止盈对下行的影响比 148 **大 4.5 倍** (p10 漂移
    21pp vs 4.7pp)。
  **用户可直接重排该列表改优先级。**

### 📐 三张独立订单, 不是一张 3 contracts 的单 (本设计的要点)

红线9 的「整单跳过不缩量」按**单笔**判:
- 三张独立单 → cap 不足时**「能买几张买几张」**;
- 合成一张 → 凑不出全额就**一张都不买**。

当日现金 $293.53 / 净值 $9,816, 三档合计约 $5,240 = 53.4% —— 这个区别不是理论上的。

### 引擎改动 (`scripts/qqq_leap.py`)

| 位置 | 改动 |
|---|---|
| `_pick` | 加 `rung=None` 参数, 非空时用该档的 `target_dte_calendar` / `dte_band_calendar` 覆盖全局值; **delta 带 / 点差闸 / min_bid 仍全局共用** |
| `cmd_window` | `need_chain` 变成**数组** (每档一个到期+行权价区间, 各档按自己的 T 反解 delta 0.20~0.50 的行权价带); 三档报价落进同一个 chain 文件即可 |
| `cmd_signal` | 逐档循环: 选档 → 定量 (梯子模式每档固定 1 张) → **逐档过资金闸** (cap 递减) → 各自成一条 buy; 新增 `rung` 与 `cap_remaining_after` 字段; `chain_diag` 按档分键 |
| `cmd_signal` | 新增 `duplicate_occ_across_rungs` 守卫 |

⚠️ **梯子模式下 `sizing.position_pct_of_portfolio` 不参与定量** (每档固定 1 张)。
每信号总规模由「净值 20% 目标仓 → 常退化成 1 张」变为「三档单价之和 ≈ 净值 53%」。
这是**用户知情选择的 sizing 放大**, 不是自学习 (红线8)。

`ladder` 空或缺失 → **完整回落单档模式**, 行为与改前逐字段一致。

## ⚠️ 当前不会成交 (必须让用户知道)

现金 **$293.53** vs 三档合计约 **$5,240**。下一次 QQQ 跌 ≥2% 时:
- 按 cap 逐档判, **三档很可能全部跳过**;
- 要三档齐发需现金 ≈ $5,240 (净值 53%);
- 只够一档时会买 **148 那张** (约 $1,599) —— 恰好是研究最支持的那档, 这是把 148 排在列表第一位的
  附带好处。

## ⚠️ 一个与研究结论的张力 (陈述, 用户已定)

10-22 的研究显示 **330 档显著最差** (被 9.94% 点差吃掉)。梯子固定包含 330, 等于每次信号都往
最差的那档投约 $2,440 (占三档总额 47%)。用户选梯子的逻辑是**分散期限与点差风险**, 这有其道理;
但若日后想砍掉 330, 只需从 `contract.ladder` 删掉第三项, 无需改引擎。
