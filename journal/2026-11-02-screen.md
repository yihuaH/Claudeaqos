## 1. 🔴 中途查出: 管线"报完成"但其实在用上周的数据

### 现象

步骤 a-c 跑完后输出里有一个 **HTTP 400 traceback**, 但紧接着又打印了
`470日日线标的数: 1000` 和 `=== a-c 完成 ===`, 退出码 **0**。报错了还说成功。

### 根因 (两层, 第一层是我自己的 bug)

**① 我取错了 JSON 键**: `pool.json` 的顶层键是 `['pool', 'dollar_volume']`, **没有 `symbols`**。
我写的转换是 `s = p.get('symbols') or p` —— 回落到字典本身, 迭代字典得到的是**键名**,
于是 `pool_syms.json` 变成了 `{"symbols": ["pool", "dollar_volume"]}` (38 字节, 2 个假 ticker)。
那个 HTTP 400 就是拿这两个假 ticker 去请求 Alpaca 的结果。

**② 失败被三重掩盖**:

| 机制 | 实测 |
|---|---|
| `integrations.py bars` 遇假 ticker | 退出码 **1**, 且**不产生输出文件** |
| `set -e` 在管道内的子 shell | **没有中止** —— `(set -e; false; echo X) \| cat` 照样打印 X |
| `… 2>&1 \| tail -25` | 管道退出码变成 `tail` 的 **0**, 且只剩尾部 25 行 (前面几步日志全丢) |

=> 命令失败 → 不中止 → 退出码 0 → 日志被截断 → 下游读到**上周残留的 `p2.json`** → 报"完成"。

### 后果 (未发生, 但只差一步)

`p2.json` 的 mtime 是 **2026-10-26 17:12:51**, 最后一根 bar 是 **10-26** —— 整整上周的文件。
**若直接往下跑 `rank` + `finalize`, 就会用上周的 470 日历史产出一个新池, 并把它标成
`generated: 2026-11-02`。** 即对外声称新鲜、实际陈旧, 且无任何痕迹。

📌 **这与「已知未修的问题 #1」(纸面 stale-fills) 是同一机制**: 某步失败不写文件 →
下游把上一轮残留当新鲜数据读。#1 的最小修法是「run 前 `unlink`」, 本次正是照它做的。

### 处置

1. 修正取键: `s = p['pool']`, 并加断言 (`len==1000` 且全为 str)。
2. **先 `rm p2.json` 再重跑** —— 这样失败就不可能被悄悄复用。
3. 重跑后核验: mtime **2026-11-02 18:16:03** / `symbols_with_data: 1000` /
   与 `pool_syms` 对齐 **1000/1000** / 首根 2025-07-21 **末根 2026-11-02 (今天)** ✅
4. 此后每一步都**显式打印退出码**, 不再用 `| tail` 吞掉。
