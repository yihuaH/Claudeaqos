## 📌 新发现: `signals.py` 部分卖出不更新 `cost`, 与加仓机制叠加会算错均价

查动量账本时发现 QQQ 一条记录对不上:

| 字段 | 值 |
|---|---|
| qty | 0.572748 |
| entry_price | 709.37 |
| qty × entry_price | **$406.29** |
| **ledger `cost`** | **$7,499.99** (**18.46×**) |

**成因**: 08-04 轮动卖掉 QQQ 10 股 (原持 10.5727), `signals.py:550-556` 的卖出分支
**只更新 `qty`, 不动 `cost` 与 `entry_price`**:

```python
remaining = float(book[sym]["qty"]) - qty
if remaining <= 1e-6:  del book[sym]
else:                  book[sym]["qty"] = round(remaining, 6)   # cost/entry_price 原样留着
```

**为什么这不只是"显示难看"**: 加仓分支 (`signals.py:527-535`) 用 `cost` 推算新的加权均价 ——
`new_cost = old_cost + qty*price`, `entry_price = new_cost / new_qty`。
所以 **「部分卖出 → 之后对同一标的加仓」** 会把被夸大的 `cost` 带进加权计算,
算出**错误的均价** → 错误的**止损线**与**加仓触发线** (两者都以加权均价为基准, CLAUDE.md 不变量)。

**现状排查 (四本账本全扫)**:

| 账本 | 结果 |
|---|---|
| `state/positions.json` (**实盘**) | ✅ **一致, 无污染** |
| `state/paper_positions.json` (挑战者) | ✅ 一致 |
| `state/stock_positions.json` | ✅ 一致 |
| `state/momentum_positions.json` | ⚠️ **1 处** (QQQ, 18.46×) |

**实盘目前没中招**, 因为实盘出场 (`exit_strength` / 止损 / 时间止损) 都是**整仓卖出**,
走的是 `del book[sym]` 那一支。会产生部分卖出的只有 **funding_rotation / accelerated_liquidation**,
而这两类自 09 月以来没触发过。但**代码路径是共用的** —— 一旦某天先部分换仓、后对同一票加仓,
实盘就会算出错的均价。

**没有自行修改任何代码** (红线2/8: 引擎逻辑改动需用户批准)。两种修法供用户选:
1. **按比例缩减** (推荐): 部分卖出时 `cost *= remaining/old_qty`, `entry_price` 不变 —— 保持
   `cost == qty × entry_price` 的不变量, 加仓加权计算自然正确
2. **不存 cost, 每次由 qty×entry_price 推导** —— 消除这个字段的不一致可能, 但要改所有读 `cost` 的地方

`skipped: ["QQQ sell: 排队限价下买不起 1 整股, 跳过"]` + `orders: []`。无害 (没有待回收的单),
