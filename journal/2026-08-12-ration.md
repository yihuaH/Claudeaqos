# 2026-08-12 · 资金配给规则研究 — 否决改动, 线索关闭

触发: 用户问「执行单可以根据 RSI2 按比例买入吗」→「跑」。
背景: 当日 4 张买单合计 $2,491.60, 而 cap 仅 $1,334.40, seq3/seq4 被整单跳过。

## 先厘清: 这是两个不同的问题

| 问题 | 状态 |
|---|---|
| **仓位大小按 RSI2 强度倾斜**（买多买少） | **08-07 已测并关闭** (`2026-08-07-scale-in.md` §二): 均值/笔全部钉在 0.56~0.58%, 倾斜只改敞口不改质量 |
| **资金不够时的配给规则**（怎么分这笔钱） | **本次新测** —— 08-07 未覆盖 |

现行规则其实**已经是 RSI2 优先**的, 只是离散的: seq 顺序 = RSI2 升序, cap 天然先喂最强信号。
用户问的是改成**按强度比例摊薄**。

## 四种配给规则

只在**资金受限的那些天**才有差别; 钱够时四者完全相同。

| 代号 | 规则 | 当前用在哪 |
|---|---|---|
| **A** | 排队填满 + 最后一单缩量到可用现金 | **回测** (`learn.py:simulate`, `addon_bt`) |
| **B** | 排队填满 + 装不下的整单跳过不缩量 | **实盘 4C** (红线2) |
| **C** | 可用现金等额摊到当日全部候选 | — |
| **D** | 可用现金按 RSI2 强度加权摊薄 | — |

C/D 带一次再分配 (被 `min(usd, share)` 削掉的余额回摊给没吃饱的单), 免得摊薄方案被闲置现金人为拖累;
任何一单**不得超过引擎给的 usd** (绝不放大)。脚本 `scratchpad/ration.py`, 样本 2022-11-01 → 2026-07-20。

## 决定性证据: 排序在两份配置之间**整个翻转**

- 不含加仓: **B 最好** (102.0%), D 第二 (98.9%), C 垫底 (95.1%) —— B 领先 C **6.9pp**
- 含加仓: **D 最好** (119.4%), B **垫底** (114.7%) —— B 落后 D **4.7pp**

同一份数据、同一批规则, 只是换了个配置, 冠亚军就对调。这是**噪声的指纹, 不是信号**。

佐证两条:

1. **每笔收益 bootstrap 全部跨 0** (4000 重采样):

| 对比 | 不含加仓 | 含加仓 |
|---|---|---|
| C 减 B | −0.032pp [−0.286, +0.218] ❌ | −0.020pp [−0.259, +0.220] ❌ |
| D 减 B | −0.037pp [−0.286, +0.223] ❌ | −0.032pp [−0.269, +0.196] ❌ |
| A 减 B | −0.035pp [−0.286, +0.233] ❌ | +0.009pp [−0.238, +0.260] ❌ |

2. **均值/笔在各规则间几乎不动** (不含加仓 0.51~0.55%, 含加仓 0.83~0.88%) ——
   与 08-07 「仓位倾斜不改变交易质量」同一形态。配给规则决定钱怎么摆, 不决定每笔赚多少。

## 摩擦: 摊薄多下 19~28% 的单, 且无稳定赢家

订单数: 不含加仓 C/D 1610/1608 vs B 1352 (**+19%**); 含加仓 1830/1837 vs 1431 (**+28%**)。

| bp | 不含加仓 A/B/C/D | 含加仓 A/B/C/D |
|---|---|---|
| 0 | 98.4 / **102.0** / 95.1 / 98.9 | 118.6 / 114.7 / 115.1 / **119.4** |
| 5 | **89.7** / 89.6 / 82.8 / 86.4 | 106.1 / 107.4 / 108.0 / **110.2** |
| 10 | **76.4** / 76.3 / 70.9 / 74.6 | 95.8 / 90.0 / 93.9 / **97.0** |
| 15 | 64.5 / **65.7** / 60.1 / 64.0 | **87.5** / 81.2 / 80.4 / 83.1 |
| 20 | 52.8 / **53.2** / 49.7 / 52.7 | **70.8** / 64.9 / 67.6 / 67.0 |

含加仓那栏冠军在 D→D→D→A→A 之间跳来跳去, **没有任何一条规则在摩擦维度上稳定占优**。
而实盘混合执行每单最多两腿、②腿是分数股市价吃开盘点差, 真实摩擦绝不是 0bp ——
多下 19~28% 的单是**确定的成本**, 换来的是**测不出的收益**。

## 结论与建议

**不改 4C。** 理由三条, 缺一不可:
1. 四种规则的每笔期望在统计上不可区分 (6 个 bootstrap 区间全跨 0);
2. 总收益排序在两份配置间翻转 → 表面差异是路径噪声;
3. 摊薄的**成本是确定的** (多 19~28% 订单 × 真实点差), **收益是测不出的**。

且改动会触碰红线: 4C 明写「超出的整单跳过**不缩量**」(红线2 引擎金额确定性),
而摊薄等于把单仓从 10% 压到 5% 左右, 动的是 `position_pct_of_portfolio` (红线3 用户参数 / 红线8 永不自学习)。

**本线索关闭**, 与 08-07「按信号强度定仓位」一并归档, 不再重复研究。

## ⚠️ 顺带发现: 回测与实盘的配给口径不一致 (待用户定夺)

`learn.py:simulate` 与 `addon_bt` 用的是 **A (缩量)**, 实盘 4C 用的是 **B (整单跳过)**。
即**参数学习器一直在用一个与实盘不同的资金规则给挑战者打分**。

影响量级: A 减 B 的每笔差 −0.035pp (不含加仓) / +0.009pp (含加仓), **两者都跨 0** ——
属口径正确性问题, 不是性能问题, 且方向无害 (实盘规则不比回测假设差)。

建议把 `learn.py:simulate` 的 `amt = min(pos_usd, cash - reserve)` 改成实盘的整单跳过语义,
让学习器评的是实际会发生的事。**本次未改** (红线8: 学习器口径属风控相关, 需用户批准)。
