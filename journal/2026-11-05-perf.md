# 2026-11-05 性能精简 (用户「精简代码, 每次运行时间太长了」)

## 先量再砍 —— 瓶颈不在 Python

| 项 | 实测 |
|---|---|
| 驱动器 `daily.py` 全程 | **18.4s** (preclose) / 8.8s (wrapup) |
| └ `bars` (拉日线) | **13.4s** ← 最慢的一步 |
| └ `macro` (FRED VIX) | 2.1~2.8s |
| └ `integrations.status` | 0.9~1.7s |
| └ `signals.signal` / `qqq_leap.window` / `position_check` | 各 ≤0.2s |
| **`allsyms` 标的数** | **126 只** |

=> 18 秒的 Python **不是**「运行时间太长」的来源。真正的时间在**会话取数**:
126 只标的要分 **7 批**调 `get_equity_quotes` (每批一个往返 + 约 6k tokens 上下文),
`bars` 也按 126 只拉。**而唯一在跑的 QQQ LEAP 只需要 1 只标的。**

## 根因

`collect_symbols` 里 `momentum` / `option` / `sqqq_short` / `leap` **都已检查 `enabled`**,
但最大的两组**没有**:

```python
groups["etf"]        = list(cfg.get("etf_universe", []))   # 8 只, 无条件
groups["stock_pool"] = list(uni.get("symbols", []))        # 100 只, 无条件
```

RSI-2 轨道 2026-11-05 退役后, 这 108 只**没有任何在跑轨道会读**, 但驱动器照旧为它们
拉日线、要报价, 且覆盖率硬闸 (<90% 拒跑) 按 126 只算。

## 改动 (15 行增 / 3 行删, 只动 `collect_symbols`)

```python
rsi2_on = bool(cfg.get("enabled"))
groups["etf"]        = list(cfg.get("etf_universe", [])) if rsi2_on else []
groups["stock_pool"] = list(uni.get("symbols", []))      if rsi2_on else []
```

### 为什么安全 (写进了 docstring)

这两组是**入场候选池**, 只被 `signals.py` 的选股循环读; `enabled=false` 时该循环本就不出订单。
**持仓是另外几组, 且一律无条件并入** (`live_holdings` / `overnight_holdings` / 各轨道账本) ——
所以**出场永远有报价**, 不会出现「轨道关了但持仓卖不掉」(红线6)。
⚠️ 这是关键区分: 我**没有**动任何持仓派生的组。`paper_holdings`(7) 与 `option`(1) 虽然也来自
已退役轨道的账本, 但它们是持仓派生的 —— 为省 8 只标的去碰那条纪律不值得, 故保留。
