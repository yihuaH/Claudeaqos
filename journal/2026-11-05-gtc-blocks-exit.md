## 🔴 层 3 (真问题): 常驻 GTC 锁住合约, 会挡掉引擎自己的时间止损

对 755C 做了一次只读 `review_option_order` (卖平, 限价 6.46 = bid×0.97, 即时间止损会用的形态),
券商原文返回:

```
alertType: OPTION_NOT_ENOUGH_CONTRACTS_TO_CLOSE
closableQuantity:     "0"     ← 可平数量 0
pendingOrderQuantity: "1"     ← 被常驻 GTC 占住
canCancelPendingOrders: true  ← 可撕, 故可修
```

即**时间止损 / `force_exit_dte` / 用户手动卖出, 全都会被「数量不足」拒掉**。
`get_option_positions` 的 `pending_sell_quantity: 1.0000` 早就在明示这件事, 我昨天没读出其含义。

### 为什么这比看起来严重

1. **`qqq_leap.py` 根本不知道有这张 GTC** —— 它会照常出 `time_stop` 卖单。
2. 会话去 place 被拒 → 按红线6 停手报告 → **那天的时间止损没有执行**, 仓位继续裸着跑。
3. ⚠️ **最可能的误诊**: 下一个会话看到"出场单被拒"会按既有剧本当成**平台分类器拦单**,
   退回写 `pending_orders.json` 等用户执行 —— 而真因完全不同 (撕掉 GTC 就能下),
   pending 清单上那张单**永远下不成**。这正是必须写进 CLAUDE.md 的理由。

### 修法 (已写进 CLAUDE.md「会改变当日操作的告警」)

每个窗口**执行出场前**必做:
1. `get_option_orders state=confirmed` 列出常驻 GTC;
2. 引擎若对某合约出了**任何**出场单 → **先 `cancel_option_order` 撕掉该合约的 GTC, 再下引擎那张出场单**;
3. 出场成交后**不重挂** (仓位已平);
4. 出场单最终未成交而仓位仍在 → 才重挂止盈 GTC。
