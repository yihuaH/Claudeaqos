# 2026-10-12 期权单腿通道测试 — **被平台分类器拦截, 不是券商**

- 起因: 用户 2026-10-12 「期权也只买单腿吧 自行下单」
- 性质: **基础设施测试, 非引擎订单** (同 2026-07-20 / 2026-08-21 先例); **未写任何账本**
- 结论: **用户这条指示的前提不成立** —— 换成单腿**并不能**让会话自行下期权单
- status: completed (**未重试, 未改任何策略配置**)

## 用户指示背后的前提

「只买单腿」显然是针对已知事实: 多腿不能下单, 所以才只能走 App 手动通道。
前提是 **「单腿就能自行下单」**。本次就是去验证这个前提。

## 结果

| 步 | 调用 | 结果 |
|---|---|---|
| 1 | `review_option_order` | ✅ **通过**, `order_checks: {}` 空, `customer_approval_required: false`, 返回完整报价与希腊值 |
| 2 | **`place_option_order`** | ❌ **被 Claude Code auto mode 分类器拒绝**: `Reason: [Real-World Transactions]` |
| 3 | 核查 | `get_portfolio` → `options_value: 0`, cash $1,119.16 **未变** → **没有任何订单被创建** |

**关键区别**: 第 2 步的失败**不是** Robinhood 的 400, 而是**平台分类器在调用发出之前就拒掉了**
("Permission for this action was denied by the Claude Code auto mode classifier")。
即请求**根本没到券商**, 所以账户零残留、无需撤单。

**未重试** (playbook 纪律: 被拦就是结论, 不换姿势再试)。

手动 App 通道 (playbook 4D) 对两者都仍然必需。

### 对照: 正股 place 是通的

同一天内:
- 10:48 ET **无人值守** XLU 买单 place → ✅ 通过 (`journal/2026-10-12-morning.md`)

### 顺带观察: 期权工具族在本会话内**收紧了**

place 被拒之后, 连**只读**的 `get_option_orders` 也开始返回同样的
`[Real-World Transactions]` 拒绝 —— 而同一个调用**今天 10:47 还成功过** (返回 `{"orders":[]}`)。
故第 3 步的核查改走 `get_portfolio` (不同工具族, 正常)。
记录此现象: 分类器状态似乎会在会话内随动作升级而变紧, 不是静态规则。

## 如果将来真要换单腿: 两条必须先摆上桌的事实

**① 要放弃的是一个 8 战 8 胜、从未亏过的形态**

| | 实盘 credit_put_spread | paper 单腿买 call |
|---|---|---|
| 回合数 | 8 | 16 |
| 胜率 | **8/8 = 100%** | 10/16 = **62%** |
| 累计 pnl_usd | +$573.00 | +$1,053.00 |
| pnl_pct 均值 | +4.14% | **−0.78%** |
| pnl_pct 中位 | +2.30% | +2.02% |
| **最差一笔** | **+0.90%** (最差也是赚的) | **−43.21%** |

⚠️ **口径警告**: 两列的 `pnl_pct` **分母不同** —— 价差是"占在险额(宽度−贷记)的百分比",
单腿是"占权利金的百分比"。**均值不可直接比**。可比的是: **胜率** 与 **最差一笔**。
价差形态至今**一笔未亏**; 单腿 16 笔里亏 6 笔, 含一笔 −43.21%。

单腿累计美元是正的 (+$1,053) 但**每笔百分比均值是负的 (−0.78%)** —— 说明美元收益靠少数
大名义赢家撑着, 这在 n=16 上是个明确的警告信号, 不是优势。

**② 实盘配置目前对单腿**没有任何张数上限**

`weekly_calls_live.json` 现状 (用户 2026-08-18「不设上限」设定, 但那是**为限定风险的价差形态**设的):

```
contract.max_premium_per_contract_usd : null   ← 单张权利金无上限
budget.max_open_premium_pct_of_portfolio: null ← 总在险额无上限
sizing.position_pct_of_portfolio      : 20
```

价差形态下这没问题: 每张风险 = 宽度 − 贷记, **天然有界**。
但**长 call 可以亏掉 100% 权利金**。在现金只剩 $1,119.16 的情况下, 一张不设上限的单腿
可能把大部分可用现金压在一个会归零的合约上。

对照 paper 轨道自己的配置是有闸的: `max_premium_per_contract_usd: 5000` +
`contracts_per_position: 1` + `max_open_positions: 4`。

→ **若要换单腿, 必须先由用户给一个单张权利金上限** (红线3: 风控上限只能由用户定, 我不自行设)。

## 建议

**维持现状 (credit_put_spread + 手动 App 通道)**。理由很简单: 换单腿的**唯一动机**是让会话能自行下单,
而本次测试证明**换了也下不了**。在动机消失的情况下, 用一个 8/8、最差 +0.90% 的形态去换一个
10/16、最差 −43.21% 的形态, 没有任何补偿。

若用户仍想推进, 需要两样东西:
1. 一个**单张权利金上限**的数字 (红线3);
2. 接受期权开仓**仍然**要在 App 手动按 —— 即「自行下单」这部分做不到。

另: 期权开仓被拦这件事**不影响出场**。期权出场卖单 (sell_to_close) 走的也是手动 App 通道
(2026-08-15 起的既有状态), 本次测试没有改变它。当前期权仓位为**空**, 无任何待处置合约。
